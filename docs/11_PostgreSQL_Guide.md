# 💾 'Project: Cortex' 개발 환경 데이터베이스 관리 가이드

이 문서는 'Project: Cortex'의 로컬 개발 환경에서 PostgreSQL 데이터베이스를 관리하는 절차와 주요 SQL 명령어를 안내합니다.

---

## 1. 개발 시작 시 (매일 컴퓨터를 켜고 개발을 시작할 때)

### 목표

이전에 저장된 데이터를 사용하여 데이터베이스 서비스를 시작합니다.

### 절차

1.  **프로젝트 루트 폴더로 이동:**

    ```bash
    cd /path/to/your/Cortex/
    ```

2.  **Docker 컨테이너 시작:**
    PostgreSQL과 Redis 컨테이너를 백그라운드에서 실행합니다. 이 명령은 이전에 생성된 데이터베이스 볼륨을 다시 연결하여 데이터를 그대로 사용합니다.

    ```bash
    docker-compose up -d
    ```

3.  **PostgreSQL 컨테이너 완전히 시작될 때까지 대기:**
    `docker-compose up -d` 실행 후, PostgreSQL 컨테이너가 완전히 부팅되고 클라이언트 연결을 받을 준비를 마칠 때까지 최소 **10~20초** 기다립니다. (시스템 성능에 따라 시간이 달라질 수 있습니다.)

4.  **확인 (선택 사항):**
    다른 터미널에서 `docker logs cortex-db -f` 명령을 실행하여 로그 마지막에 `database system is ready to accept connections` 메시지가 나타나는지 확인합니다.

---

## 2. 개발 종료 시 (컴퓨터를 끄거나 개발을 마칠 때)

### 목표

데이터베이스 컨테이너를 안전하게 중지하여 데이터 손상을 방지합니다.

### 절차

1.  **모든 서버 프로세스 종료:**
    FastAPI 웹 서버(`uvicorn`), Celery 워커(`celery`), Next.js 개발 서버(`npm run dev`)가 실행 중인 모든 터미널에서 `Ctrl+C`를 눌러 프로세스를 종료합니다.

2.  **프로젝트 루트 폴더로 이동:**

    ```bash
    cd /path/to/your/Cortex/
    ```

3.  **Docker 컨테이너 중지:**
    PostgreSQL과 Redis 컨테이너를 중지합니다. 이 명령은 데이터를 삭제하지 않고 컨테이너만 정지시킵니다.
    ```bash
    docker-compose down
    ```

## 3. 데이터베이스 스키마 변경 시 (`models.py`를 수정했을 때)

### 목표

변경된 SQLAlchemy 모델을 데이터베이스에 반영합니다. **기존 데이터는 유지됩니다.**

### 절차

1.  **모든 서버 프로세스 종료:** ("2. 개발 종료 시"의 1번과 동일)
2.  **Docker 컨테이너 시작:** `docker-compose up -d`를 실행하여 PostgreSQL 컨테이너가 실행 중인지 확인하고, 완전히 시작될 때까지 기다립니다.
3.  **백엔드 폴더로 이동 및 가상 환경 활성화:**
    ```bash
    cd backend
    # Windows
    .\venv\Scripts\activate
    # macOS/Linux
    # source venv/bin/activate
    ```
4.  **Alembic 마이그레이션 스크립트 생성:**
    `models.py`의 변경 사항을 감지하여 새로운 마이그레이션 스크립트 파일을 생성합니다.

    ```bash
    alembic revision --autogenerate -m "변경 사항에 대한 설명 메시지"
    ```

    > **⚠️ 중요:** 생성된 `.py` 파일을 열어 `upgrade()`와 `downgrade()` 함수에 예상한 스키마 변경 코드가 포함되어 있는지 반드시 확인합니다.

    `backend/migrations/versions/`에 생성된 마이그레이션 코드를 수정합니다. (상단과 하단의 ohlcv 관련 마이그레이션 코드를 초기화)

    ```python
    TIMEFRAMES = ["1m", "5m", "15m", "30m", "1h", "4h", "1d", "1w", "1M"]

    def upgrade() -> None:
        """Upgrade schema."""
        # ### commands auto generated by Alembic - please adjust! ###
        print("Creating OHLCV hypertables and indexes...")
        for tf in TIMEFRAMES:
            table_name = f"ohlcv_{tf}"

            # 2-1. 기본 테이블 생성
            op.create_table(
                table_name,
                sa.Column('time', sa.DateTime(timezone=True), nullable=False),
                sa.Column('ticker', sa.Text(), nullable=False),
                sa.Column('open', sa.Float(), nullable=False),
                sa.Column('high', sa.Float(), nullable=False),
                sa.Column('low', sa.Float(), nullable=False),
                sa.Column('close', sa.Float(), nullable=False),
                sa.Column('volume', sa.Float(), nullable=False),
                # Upsert를 위한 복합 기본 키 설정
                sa.PrimaryKeyConstraint('time', 'ticker')
            )

            # 2-2. (매우 중요) 생성된 테이블을 TimescaleDB의 하이퍼테이블로 변환
            op.execute(f"SELECT create_hypertable('{table_name}', 'time', if_not_exists => TRUE);")

            # 2-3. 데이터 조회 성능 최적화를 위한 복합 인덱스 생성
            op.create_index(f'idx_{table_name}_ticker_time_desc', table_name, ['ticker', sa.text('time DESC')])

            print(f"Table '{table_name}' created and converted to hypertable.")
    ```

    ```python
    # 3. 모든 하이퍼테이블을 삭제하는 수동 스크립트를 추가합니다.
    print("Dropping OHLCV hypertables...")
    for tf in TIMEFRAMES:
        table_name = f"ohlcv_{tf}"
        op.drop_table(table_name)
        print(f"Table '{table_name}' dropped.")
    # ### end Alembic commands ###
    ```

5.  **Alembic 마이그레이션 적용:**
    ```bash
    alembic upgrade head
    ```
    이 명령이 성공적으로 실행되면, 데이터베이스 스키마가 업데이트됩니다.

## 4. 데이터베이스 오류 발생 시 (초기화)

### 목표

손상된 데이터베이스를 완전히 초기화하고 깨끗한 상태에서 다시 시작합니다. **이전 데이터는 모두 삭제됩니다.**

### 증상

`FATAL: the database system is starting up`, `PANIC: could not locate a valid checkpoint record`, `Connection refused` 등.

### 절차

1.  **모든 서버 및 컨테이너 종료:**
    실행 중인 모든 서버 프로세스를 종료하고, 프로젝트 루트에서 다음 명령을 실행하여 컨테이너와 **데이터 볼륨**을 완전히 삭제합니다.
    ```bash
    docker-compose down -v --rmi all
    ```
2.  **남은 Docker 볼륨 수동 확인 (필수):**

    - Docker Desktop 앱의 **"Volumes" 탭**에서 `cortex` 관련 볼륨이 남아있다면 모두 수동으로 삭제합니다.
    - (권장) `docker system prune -a --volumes` 명령으로 전체 Docker 캐시를 정리합니다.

3.  **Alembic 마이그레이션 파일 삭제:**
    `backend/migrations/versions/` 디렉토리의 모든 `.py` 파일을 삭제합니다.

    ```bash
    # Windows PowerShell 기준
    rm backend\migrations\versions\*.py
    ```

4.  **데이터베이스 재생성:**
    - `docker-compose up -d`로 컨테이너를 새로 시작합니다.
    - 백엔드 가상 환경을 활성화하고 `alembic revision --autogenerate -m "Initial migration"`으로 첫 마이그레이션 파일을 생성합니다.
    - `alembic upgrade head`를 실행하여 데이터베이스에 모든 테이블을 생성합니다.

## PostgreSQL 기본 SQL 명령어 가이드

### 접속 방법

    psql 클라이언트를 사용하여 Docker 컨테이너에서 실행 중인 데이터베이스에 접속합니다.

    ```bash
    docker exec -it cortex-db psql -U cortex_user -d cortex_db
    ```

### 1. 메타 정보 조회 (`psql` 전용)

    psql 내부에서 데이터베이스의 구조를 확인하는 데 사용되는 명령어입니다.

    | 명령어             | 설명                                                                              |
    | ------------------ | --------------------------------------------------------------------------------- |
    | `\dt`              | 현재 데이터베이스의 모든 테이블 목록을 조회합니다.                                |
    | `\d <테이블_이름>` | 특정 테이블의 상세 스키마(컬럼, 타입, 제약조건 등)를 조회합니다. (예: `\d users`) |
    | `\q`               | psql 클라이언트를 종료합니다.                                                     |

### 2. 데이터 조회 (SELECT)

    테이블에서 데이터를 검색합니다.

    ```sql
    -- 모든 사용자 조회
    SELECT * FROM users;

    -- 특정 이메일을 가진 사용자 조회
    SELECT * FROM users WHERE email = 'test@example.com';

    -- 최근 가입한 순서대로 5명의 사용자 조회
    SELECT * FROM users ORDER BY created_at DESC LIMIT 5;
    ```

### 3. 데이터 삽입 (INSERT)

    테이블에 새로운 행(row)을 추가합니다.

    ```sql
    INSERT INTO users (id, email, hashed_password, is_active, role, created_at, updated_at)
    VALUES (gen_random_uuid(), 'new@example.com', 'hashed_pw', TRUE, 'user', NOW(), NOW());
    ```

### 4. 데이터 수정 (UPDATE)

    기존 행의 데이터를 변경합니다.

    > **⚠️ 경고:** `WHERE` 절을 생략하면 **테이블의 모든 행이 수정**되므로 매우 주의해야 합니다.

    ```sql
    UPDATE users SET role = 'admin' WHERE email = 'test@example.com';
    ```

### 5. 데이터 삭제 (DELETE)

    테이블에서 특정 행을 제거합니다.

    > **⚠️ 경고:** `WHERE` 절을 생략하면 **테이블의 모든 데이터가 삭제**되므로 매우 주의해야 합니다.

    ```sql
    -- 특정 사용자 삭제
    DELETE FROM users WHERE email = 'delete_me@example.com';

    -- 테이블의 모든 데이터 삭제 (구조는 유지)
    TRUNCATE TABLE users;
    ```
